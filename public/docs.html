Atlas Documentation

Everything you need to make maps in the Studio, publish open datasets, and render Atlas maps inside your own applications with the REST API and SDK.

Getting started

git clone <this repo>
npm start          # → http://localhost:8787
npm test           # run the test suite

Atlas needs only Node 18+ (Node 22+ recommended — accounts and logging use the built-in SQLite database). There are no npm dependencies and no API keys for basemaps: all seven basemap styles use open, key-free tile services. A sample dataset (acme-locations) is seeded on first run so every feature is demoable immediately.

Using the Studio

Open /studio. The sidebar is your workflow, top to bottom:

  1. Account — sign in (or register) to publish datasets and get an API key. Browsing, importing, and exporting work without an account.
  2. Find a place — type any country, city, address, or landmark. Picking a result flies the map there.
  3. Basemap style — switch among Streets, Bright, Light, Dark, Satellite, Terrain, and OpenStreetMap. Your data layers survive style switches.
  4. Data — import a CSV or GeoJSON file, or add a published dataset from the server. CSV latitude/longitude columns are auto-detected (lat/latitude/y and lng/lon/longitude/x); all other columns become feature properties.
  5. Layers on map — each layer has its own map type and value property. Switch them live; the legend updates automatically.
  6. Map output — set a title, toggle the legend, fit to data, export a PNG, or open Share & embed.
Example workflow: search "United States", import locations.csv from your CRM, switch the layer to Bubble map with revenue as the value property, type a title, and export a PNG — legend included.

Legends are generated automatically from each layer's map type, value property, and the actual minimum/maximum in your data. They render as an on-map overlay (toggleable) and are always composited into PNG exports, together with the map title and basemap attribution.

Sharing & embedding

The Studio's Share & embed dialog produces three artifacts, all reproducing your exact view, style, map type, title, and legend:

  • Shareable link — a full-page interactive map (/embed?…). Recipients can pan, zoom, and click popups.
  • iframe snippet — paste into any website or CMS; zero JavaScript required.
  • SDK snippet — for embedding the map natively in your own application.

Sharing data layers requires the dataset to be published first (a link can't carry your local file). The dialog detects unpublished layers and tells you.

Authentication

Atlas has two credential types:

  • Session cookie — created by signing in via the Studio (or POST /api/auth/login). HttpOnly, 30-day expiry. Used by browsers.
  • API key — issued at registration; view it via the Studio's Show my API key. Send it as Authorization: Bearer <key> for server-to-server calls.

Passwords are hashed with scrypt and a per-user random salt; comparisons are timing-safe. Reading data never requires auth; publishing and deleting datasets do. Only a dataset's owner may delete it.

# Register (also signs you in and returns your API key)
curl -X POST http://localhost:8787/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"s3cret-pass","name":"You"}'

# Publish a dataset with your API key
curl -X POST http://localhost:8787/api/datasets \
  -H "Authorization: Bearer atlas_..." \
  -H "Content-Type: application/json" \
  -d '{"name":"My stores","geojson":{"type":"FeatureCollection","features":[]}}'

Open data policy

Every dataset published to an Atlas server is open data:

  • Licensed — CC BY 4.0 by default; override with a license field on upload.
  • Cataloged — listed publicly at /data with license, owner-published provenance, and links.
  • Downloadable — raw GeoJSON at GET /api/datasets/:id/download, no auth required.
  • Logged — dataset and account events are recorded in the database-backed public activity log (GET /api/log). API requests are also logged server-side (GET /api/stats, signed-in users).

The Studio warns users that publishing makes data public before anything is uploaded.

Architecture

server/index.js     zero-dependency Node HTTP server: pages + REST API
server/presets.js   basemap style + map type catalogs (extend here)
server/db.js        SQLite (node:sqlite): users, sessions, activity & request logs
server/auth.js      register / login / logout / me + request authentication
server/seed/        built-in sample datasets, seeded into data/ on first run
public/             landing (/), studio (/studio), docs (/docs), data catalog (/data)
sdk/atlas-sdk.js    the developer kit: API client + map renderer (MapLibre GL)
examples/           browser + Node integration examples
data/               runtime state: dataset files + atlas.db (gitignored)

Rendering is MapLibre GL JS. Geocoding is proxied to OSM Nominatim with caching — respect their usage policy in production or point the proxy at your own geocoder. To extend Atlas: add basemaps and map types in server/presets.js, layer renderers in LAYER_BUILDERS in the SDK, and routes in server/index.js.
